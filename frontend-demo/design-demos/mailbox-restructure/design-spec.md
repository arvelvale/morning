# DAY-252 · 信箱信息架构设计规格

## 目标

Morning 的底部“信箱”入口需要承担两类关系完全不同的内容：一类是桌宠主动写给用户的来信，核心价值是陪伴感、期待感和人与宠物之间的关系；另一类是系统帮助用户整理出的思绪、待办、珍藏和短期寄存，核心价值是回看、决定去留和继续行动。当前实现把四种分区并列放进同一个信箱，导致“桌宠来信”与“思绪整理结果”共享同一层级，用户难以建立稳定心智模型。此次设计先只做高保真交互原型，不修改生产接口、数据结构和现有业务行为。

## 用户与场景

主要用户在手机上以短时、低认知负担的方式打开应用：收到桌宠来信时希望直接看到信件，不想先理解内容分类；睡前倾倒或日常整理后，希望在同一底部入口中找到系统收好的思绪，但需要明确知道这些内容不是桌宠“写来的”。Web 端同样重要，需把相同概念扩展为侧栏和内容区，而不是简单拉宽手机布局。

## 必须表达的结构

- “来信”只承载桌宠主动内容，保留拆信、收到、回信、留下等关系型动作。
- “思绪”是独立空间，聚合今日待启、长久珍藏和三日寄存；这些类别可作为思绪空间内部筛选，不与来信并列。
- 底部主导航仍只有“陪伴 / 信箱 / 片场 / 我的”，不新增第五个主入口。
- 原型使用仓库现有真实文案语义与示例条目，不编造统计成绩、人格判断或敏感内容。
- 日间采用现有暖奶油背景、鹅黄强调和暖棕前景；仅使用系统无衬线字体；按压反馈克制，不加入装饰性循环动画。

## 三个探索方向

1. **双入口切换**：信箱页顶部用“来信 / 思绪”双分段控件。最保守、学习成本最低，适合直接落地。
2. **来信主舞台 + 思绪抽屉**：打开信箱默认直达桌宠来信，思绪整理通过底部悬浮入口进入。陪伴感最强，但思绪入口的可发现性需要验证。
3. **并列双空间**：信箱首页先展示“桌宠来信”和“我的思绪”两个大空间，再进入详情。概念最清晰，代价是多一步导航。

## 输出与验收

交付一个可双击打开的单文件 HTML，包含三套可点击方案，并可切换 390×844 手机视图与 1440×900 桌面结构。每套至少能在“来信”和“思绪”之间切换，来信可展开，思绪内部可切换分类。验证要求：无控制台错误、无横向溢出、主要按钮可点、手机与桌面模式均能显示完整操作区。

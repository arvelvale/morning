# 2026-09-26 · 喵灵数据库 PostgreSQL 化第一阶段

## 产品语义

后端现在可以按配置选择 SQLite 或 PostgreSQL；当前线上默认数据库不变。增加旧库到专用空 PostgreSQL 库的复制工具，迁移前先只读盘点，复制后逐表核数并保留原主键。切换属于另一道发布操作：须停写、做一致性备份、预演真实用户路径与回滚，不能把其他项目的数据库直接当喵灵库。

## 技术实现

- `backend/app/db.py` 仅为 SQLite 注入 PRAGMA/线程参数；业务层 JSON 包含查询与验证码锁按方言分支。
- `backend/alembic/versions/018_mailbox_delivery_guard.py` 增加 PostgreSQL 旧信日期回填语句；容器入口根据数据库表和迁移版本判定升级路径。
- `backend/scripts/migrate_sqlite_to_postgres.py` 只读审计默认开启；`--copy` 需专用环境变量和空库，复制数据、重置序列、打 Alembic 标记。
- Compose 改为只从线上 `.env` 读取数据库地址；独立 PostgreSQL 服务使用 `pg` profile 和专属数据卷。部署同步保留数据库地址与密码；备份步骤按数据库类型使用 SQLite backup API 或 `pg_dump -Fc`。迁移步骤见 `backend/README.md`。

## 验证与待实测

- 本地 SQLite 快照只读审计：20 张表、47 行；邮箱登录回归 16 项通过。
- 本机没有运行中的 PostgreSQL 或 Docker daemon，故在喵灵线上服务器的独立 PG 容器中完成了预演与最终切换。最终 SQLite 静止快照 31,634 行，逐表行数与逐行内容摘要核对通过；线上后端 PostgreSQL、Alembic 019、容器健康检查及鉴权后的用户/会话/记忆/信件 HTTP 读取通过。切换后 `pg_dump -Fc` 备份已实际恢复到临时数据库并核对 39 个用户，之后清理了临时恢复库。SQLite 快照和旧镜像保留在服务器，供审慎回滚；PG 切换后的新增数据不能靠旧 SQLite 快照恢复。
- 正式运行镜像使用旧后端镜像作为底座、增量安装 PostgreSQL 驱动并覆盖当前已提交后端代码及本次 PG 改动；未包含本地其他未提交的片场/信箱代码。标准 Dockerfile 的全量重构建下载依赖耗时较长，验证构建在依赖安装阶段主动停止；后续发布前仍需完成一次标准全量构建。线上镜像和数据库继续保持健康。

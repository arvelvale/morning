## 鸿蒙版：睡前倾倒（文本）+ 信箱闭环

### 第一层（产品语义）

**做了什么。** 鸿蒙版补齐了两块核心业务：一是「睡前倾倒」——用户把今晚没闭环的事写成一段话交给喵灵，整理过程实时可见（分好一条就出现一条，标注是待办、灵感、情绪还是片段），结束后给一张回执，并可以一键去信箱看结果；二是「信箱」——从占位卡片变成真正能用的两层结构：「来信」层收桌宠寄来的信（点开即读、可以回一句「收到啦」，桌宠会就地回一句短回应），「思绪」层收倾倒分好类的念头（待办可以勾完成，灵感安静陈列，带保存期的思绪可以「珍藏」留下或「放下」），另有一个不抢眼的「我留下的」入口收长久珍藏。

**为什么这样做。** 按 8-27 计划，M0–M2（构建基线、伙伴首页、流式聊天）已完成，下一切片是 M3/M4。语音必须真机验收（当前无设备），所以先做不依赖设备的文本倾倒 + 信箱——它们是同一条数据流的两端（晚上倒出来 → 早上收回来），合在一起才构成完整闭环。信箱交互刻意对齐 RN 端现行版本（两层结构、批注式思绪行），不做鸿蒙独有的新交互，避免双端语义漂移。

**核心数据流。** 倾倒：文本 → 后端流式接口（SSE = 服务端单向推送，边处理边把分类结果推给客户端）→ 整理过程中逐条落库 → 回执（各类目计数 + 明细）→ 信箱各层按类别读取展示。即使整理中途失败，原文已在服务端安全保留，回执会明确说明（fallback = 兜底：AI 没完成分类时系统给出的保底说明，原文不丢）。

**兼容性。** 全部复用既有后端接口，无后端改动；安卓/Web 端行为不受影响。倾倒的语音输入路径（录音→转写）按计划在 M3 真机阶段补。

- 本次只完成编译级验证（ArkTS 类型检查 + debug 签名包构建成功），倾倒流式整理、已读同步、「收到啦」回应、待办完成、珍藏/放下都**需要真机或云调试实际跑一遍**。

## 修正：倾倒与信箱对齐 RN 端现行实现

### 第一层（产品语义）

**问题。** 第一版信箱/倾倒只对照了接口契约和后端文档，没有逐屏对照安卓（RN）端最近大改后的实现，导致多处语义不一致：「收到啦」永远只显示兜底文案（读错了回应字段）；待办只能单向完成、看不到已完成项；来信没有拆信仪式和「留下/回信」动作；倾倒回执没有「接住 N 个念头」的分类汇总和「明天最值得关注」高亮。

**修正后的一致性。** 两个页面逐屏对齐 RN 端现行版本：

- 来信：最新一封有「轻点拆开」的信封仪式，拆开后是信纸（日期抬头、正文、桌宠落款），可「收到啦」（桌宠就地回一句）、「回它一句」（跳回陪伴页开聊）、「把这封信留下」（收进「我留下的」，不留则明天新信到达时离开）；场景邀请信有「进入场景」卡（接受后场景已在后端备好，片场页接通前先提示）；往期来信点开直读并顺手标已读；等待态「今天的信还在路上」。
- 思绪：待办可来回勾完成/取消（已完成划线、可移除），显示到期时间（今天 / 今天 15:00 / 8月2日）；灵感陈列；临时思绪显示「N 天后到期」、可珍藏可放下；顶部有办/想/情/景图例计数。
- 倾倒：输入页文案（「今晚的念头」「整理是我的事，你只管说」）、处理中逐条接住、回执四卡（明天要接住/值得留下的想法/被听见的感受/今晚静静收着，灵感合并小结）+ 首条待办高亮 + 失败兜底文案「今晚先替你收着了，明天再慢慢看」，按钮「今晚到这里 / 看看我替你放在哪里」。

**仍需验证**：同上午结论，全部需真机/云调试跑一遍；场景邀请的「进入场景」在片场模块（M6）落地前只做接受 + 提示。

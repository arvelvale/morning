# 开发日志规则与索引

## 规则

任务完成报告采用「产品语义优先、实现细节其次」的双层结构：

1. **第一层（产品语义）**：使用非代码语言说明——做了什么、为什么这样做、核心数据流、兼容性、风险与需要验证的内容。
2. **第二层（技术实现）**：再列出具体文件、函数、类、序列化链路等技术细节。
3. 不得仅用函数名、框架术语和文件路径描述完成结果。
4. 首次出现 fallback、normalize、透传等非基础术语时，用一句简短中文解释
   （例如：fallback = 兜底，AI 没给出合法值时系统拿来补位的默认值；透传 = 中间层不加工、原样转发数据）。
5. 每天一个文件，文件名用日期（`YYYY-MM-DD.md`）；同一天多个任务追加到当天文件中，并在本索引补充链接。

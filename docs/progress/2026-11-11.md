# 2026-11-11 开发日志

## 本地优先运行时（P0 + P1）

### 产品语义

- 用户填入自己的密钥后，可以选择“本地模式”：对话与设置存在手机里，手机直接连阶跃 / DeepSeek，不再经过喵灵服务器。目前是实验功能，默认关闭，入口在“我的 → 模型与密钥”。
- 本地模式下只有聊天（含发图）、选桌宠、偏好设置可用；记忆、待办、来信、场景、语音等接口明确提示“本地模式暂不支持”，不会悄悄回退到服务器。

### 技术实现与验证

- 设计见 [本地优先运行时](../specs/2026-11-11-local-first-runtime.md)。`frontend-demo/src/local/` 是手机里的“虚拟服务器”，`api.ts` 在本地模式下把接口调用交给它，界面代码不变。
- 提示词、换路规则从后端导出成黄金数据逐字比对（`backend/scripts/export_local_fixtures.py`）。
- `npm run test:local`、`tsc --noEmit`、其余前端脚本均通过；`expo export` 打包通过。

### 如实说明

- 没有在真机或模拟器上运行过；expo-sqlite 是新增原生依赖，需要重新出包才能验证。
- 未出 APK、未部署后端、线上 0.3.22 不含这部分。

## 本地模式：记忆与待办（P2）

### 产品语义

- 本地模式下现在能用：记忆（召回进聊天、版本历史、遗忘/清空）、待办（增改删、今日待启、聊天里说出安排自动记并出回执）、睡前倾倒、小结/灵感/情绪、三日寄存（到期真删）与长久珍藏、记忆审阅、桌宠、偏好。
- 还不能用：信箱与来信、场景、语音通话、“了解你”用户画像。

### 技术实现与验证

- 逐模块移植自后端（时间口径、MemoryStore、隐私过滤与召回、提取、倾倒编排、聊天记待办），提示词从后端导出，不手抄。
- 对照方式见 [spec §12](../specs/2026-11-11-local-first-runtime.md)：用真实后端在冻结时间下跑出黄金数据，TS 逐项比对（含倾倒后数据库里的每一行和历史）。改后端的提示词或记忆规则后要重跑 `backend/scripts/export_local_memory_fixtures.py`。
- `npm run test:local`（5 个脚本）、`tsc`、其余前端脚本、`expo export` 打包均通过；故意改坏三处逻辑（待办置信度阈值、脆弱记忆过滤、原文即焚）测试都会报错。

### 如实说明

- 仍未在真机上运行。SQLite 的 JSON 查询（倾倒回取用 `json_each`）在 `node:sqlite` 下通过，expo-sqlite 自带的 SQLite 版本未单独验证。
- 记忆召回是关键词/实体匹配（与后端一致），没有向量检索；后端的中文 bigram 与这里等价，但 Python 的 `str.isspace` 与 JS 的 `\s` 在极少数不常见的空白字符上可能有差异。
- 用户画像（每条聊天消息的内容信号提取 + 画像整合）没有移植：服务器版每发一条消息会多一次模型调用来更新画像，本地模式先不做。
- 首页的“有来信 / 今天还有 N 件待办”邀请仍为空，随信箱（P3）一起做。

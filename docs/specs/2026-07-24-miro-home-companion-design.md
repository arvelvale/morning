# 米露陪伴首页桌宠设计

## 目标

第一版只在“陪伴首页”展示米露的真实形象。首页默认显示高清透明静态图，并在适当的空闲时机播放一次舔爪动画，让米露显得有生命但不持续干扰用户。

聊天页、选宠页、个人页及其他页面暂时保留现有 emoji 或占位组件。本次不扩展其他桌宠，也不实现系统级悬浮桌宠、Live2D 或复杂动作系统。

## 角色与数据绑定

- 米露继续使用后端预设 ID `miro`。
- 米露的对话人格继续由现有 `MIRO_SYSTEM_PROMPT` 控制。
- 前端根据稳定的 `preset_id` 选择素材，不使用桌宠名称判断。
- 第一版素材映射保留在前端静态注册表中，不把本地文件路径写入数据库。
- 无法取得 `preset_id` 或素材不存在时，回退到当前 `PetPlaceholder`。

建议的素材键：

- `miro.idle`：高清透明静态 PNG。
- `miro.groom`：透明舔爪动画帧。

## 素材规范

### 静态母图

- 文件：`frontend-demo/assets/pets/miro/miro-groom.png`
- 格式：带 Alpha 通道的 PNG。
- 画布：正方形，角色完整居中，耳朵、爪子和尾巴不可裁切。
- 用途：首页动画加载前、减少动态效果、加载失败时的兜底图。

### 动画

- 动作：舔爪整理毛发。
- 时长：约 2–3 秒。
- 播放方式：单次播放，结束后回到静态图。
- 推荐输出：经过尺寸和颜色统一的透明 PNG 帧序列。
- 第一版目标帧数：24–36 帧；以视觉连贯为准，不为追求高帧率增加无效体积。
- 所有帧使用相同画布、角色锚点和裁切边界，避免播放时跳动。
- 动画素材目录：`frontend-demo/assets/pets/miro/groom/`。

原始视频仅作为动作参考，不直接进入 App：它使用 HEVC 编码且带黑色背景，跨端兼容性和视觉效果不满足正式素材要求。

## 前端组件

新增一个职责单一的首页桌宠组件，例如 `HomePetArtwork`：

- 输入：`presetId`、尺寸、是否允许动态效果。
- 输出：米露静态图或舔爪动画。
- 内部负责预加载、播放状态和降级。
- 不负责请求桌宠数据、聊天导航或业务文案。

`CompanionIdle` 继续负责首页布局与交互，只把当前桌宠的 `preset_id` 传给桌宠组件。组件不改变现有点击桌宠进入聊天的行为。

## 播放状态

首页桌宠采用以下状态：

1. `loading`：预加载动画帧，同时显示静态 PNG。
2. `idle`：显示静态 PNG。
3. `grooming`：按顺序播放舔爪帧。
4. `fallback`：出现加载或解码问题时持续显示静态 PNG。

首次进入首页先显示静态图。动画准备完成后等待一个随机空闲间隔再播放，建议 5–12 秒。单次动画结束后回到 `idle`，下一次播放间隔重新随机。

页面离开前台、首页失去焦点或组件卸载时停止计时和动画，避免后台耗电。用户快速返回首页时重新从静态状态开始，不从中间帧恢复。

## 动效与可访问性

- 系统开启“减少动态效果”时不播放动画，只显示静态米露。
- 动画不自动发声，不触发震动，不弹出提示。
- 用户点击米露仍进入聊天；点击不会强制重新播放动画。
- 动画频率保持克制，不能连续循环造成视觉压力。

## 错误处理

- 动画帧缺失、加载失败或内存压力过大：回退到静态 PNG。
- 米露静态图也无法加载：回退到现有 `PetPlaceholder`。
- 非 `miro` 桌宠：首页继续使用现有占位方案。
- 错误不阻塞首页其他内容，也不向普通用户显示技术报错。

## 性能约束

- 首页只加载当前桌宠的素材。
- 动画帧在需要时预加载，不在 App 启动阶段加载所有动作。
- 动画帧应在视觉验收后进行无损或高质量压缩。
- 实机重点检查 Android 内存、首屏时间和页面切换后的定时器清理。

## 验收标准

1. 当前桌宠为米露时，陪伴首页显示透明背景的真实米露形象。
2. 首屏立即出现静态图，不等待动画资源。
3. 动画准备完成后，米露会在 5–12 秒内播放一次完整舔爪动作并回到静态图。
4. 动画播放时角色位置稳定，无黑底、绿边、裁切或明显闪烁。
5. 离开首页后动画和定时器停止。
6. 开启减少动态效果后不播放动画。
7. 素材加载失败时首页仍可正常使用，并显示静态图或旧占位。
8. 其他桌宠和其他页面的表现不发生变化。

## 测试

- 组件测试：米露、非米露、减少动态效果和加载失败四种路径。
- 状态测试：`loading → idle → grooming → idle`，以及卸载时清理计时器。
- 视觉测试：浅色与深色主题下检查透明边缘和角色对比度。
- 实机测试：Android 前后台切换、重复进入首页、连续运行与内存占用。

## 后续扩展

第一版稳定后，可继续增加 `blink`、`listen`、`notice` 和 `sleep` 动作，并把前端素材注册表扩展成由后端返回的 `asset_key`。本次不提前实现这些能力。

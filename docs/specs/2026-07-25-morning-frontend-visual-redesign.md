# Morning 前端视觉重构设计方案

## 1. 文档目的

本文定义 Morning 前端视觉重构的范围、设计方向、响应式策略、组件边界、页面顺序、迁移方式和验收标准。后续实施必须以本文为依据，每完成一项任务并通过验证、确认后，才进入下一项。

本文只描述设计与迁移方案，不授权修改业务功能、接口、文案、页面流程或数据结构。

## 2. 当前问题

当前项目已经存在主题、公共组件和一套尚未完成的新设计系统，但没有形成统一约束：

- `theme.ts` 与 `design-tokens.ts`、`design-hooks.ts` 同时存在，主题入口和字段不统一。
- `components.tsx` 与 `design-components.tsx` 存在职责重叠。
- 页面仍大量自行定义颜色、字号、圆角、间距和控件外观。
- 日间与夜间色板字段不对称，部分组件切换夜间后仍使用固定浅色样式。
- Web 主要沿用移动端布局，没有统一的桌面导航、内容宽度和分栏规则。
- 公共组件主要覆盖触摸按压，缺少完整的 Web 悬停、键盘焦点和桌面浮层形态。
- 当前 TypeScript 基线存在错误，无法可靠判断迁移是否引入回归。

硬编码值不是唯一问题。场景素材色和图片蒙层可以合理保留；真正需要解决的是相同语义缺乏统一规则，以及不同语义被机械映射到同一个 token。

## 3. 已确认的项目范围

### 3.1 本轮包含

- 重构视觉体系和公共组件。
- 改善页面层级、颜色、排版、留白、圆角、阴影和动效。
- 为手机与 Web 分别设计合适的响应式布局。
- 日间主题进行完整设计和精细验收。
- 保留夜间模式入口，并保证其基本可读和可操作。
- 保留现有图片、角色、插画和图标，通过裁切、蒙层、留白和容器规则统一呈现。
- 修复阻塞视觉迁移和验证的设计基础层、类型及响应式问题。

### 3.2 本轮不包含

- 不新增、删除或合并核心功能。
- 不修改现有文案和主要页面流程。
- 不修改后端接口和数据结构。
- 不大规模重新制作角色、场景图片、插画或图标。
- 不全面重设计夜间主题。
- 不以“消灭全部硬编码”为目标。
- 不将现有页面做成完全不同的信息架构。

### 3.3 改动幅度

采用中度视觉优化：

- 保留现有页面骨架和信息结构。
- 允许调整页面内部留白、卡片分组、控件外观和响应式组织。
- 允许 Web 使用适合桌面的导航和分栏，但不改变导航入口和功能含义。

## 4. 视觉方向

整体关键词为：

- 温暖
- 安静
- 可信
- 留白
- 轻微纸张感

界面不依赖强烈渐变、大量毛玻璃、密集描边、夸张金色或高频动画营造质感。

### 4.1 日间基础色

以下颜色是设计起点。实施前可在独立 token 任务中做小幅可访问性校正，但不得改变整体方向。

| 语义 | 建议值 | 用途 |
|---|---:|---|
| 页面背景 | `#F7F2E8` | 全局暖奶油背景 |
| 次级背景 | `#EFE7DA` | 分组区域和次级层 |
| 卡片背景 | `#FFFCF6` | 纸张感内容容器 |
| 主文字 | `#403A35` | 标题和正文 |
| 次文字 | `#756C63` | 说明与次级信息 |
| 弱文字 | `#9D9389` | 占位和辅助信息 |
| 主强调面 | `#F0D477` | 主要按钮和需要实底承载的操作 |
| 浅强调背景 | `rgba(246,225,143,0.48)` | 图标底、轻量选中和强调区域 |
| 强调前景 | `#6E5A28` | 鹅黄色背景上的文字与图标 |
| 焦点色 | `#C39A2A` | 输入焦点、键盘焦点和必要描边 |
| 辅助疗愈绿 | `#718879` | 少量辅助状态 |
| 分割线 | `#E4DACE` | 结构分隔 |

使用规则：

- 日间模式的通用交互强调统一使用底部 Tab 同源的鹅黄色，不再使用粉红、砖红作为普通强调色。
- 主要按钮、发送、保存、确认、选中项、步骤进度、输入焦点，以及麦克风、加号等强调图标均遵循同一体系。
- 鹅黄色负责背景和操作承载面；其上的文字与图标使用暖棕色 `#6E5A28`，避免低对比度的黄色细线图标。
- 单个页面只有一个主要强调体系。
- 金色仍只用于少量特殊内容语义，不替代成功、警告、错误等状态色。
- 成功、警告、错误色只表达状态，不作为装饰。
- 卡片优先依赖背景层级和留白，减少阴影与描边。
- 图片文字、场景蒙层和素材色使用专门语义，不强制套用普通主题色。
- 本次强调色统一只修改日间模式；夜间模式 token 和视觉不在本次范围内。

### 4.2 夜间主题

- 夜间模式入口继续保留。
- 本轮只保证文字、背景、控件、焦点和关键状态具备足够可读性。
- 新增公共组件必须提供基本夜间映射。
- 夜间主题的氛围、素材融合和精细层次另列后续项目，不阻塞本轮日间交付。

### 4.3 字体与排版

不引入外部字体包。2026-09-11 按用户确认采用局部衬线、功能无衬线的分工：

- 登录欢迎语及展示引言、信件标题、片场创建引导语使用系统宋体类衬线，统一使用 `textStyles.emotionalTitle`，字重 400、自然字距。
- 导航、按钮、输入框、聊天正文（含宠物回复、首页对话摘要、语音转写）、资料名称和通用页面标题保持系统无衬线。信件正文同样保留现有无衬线。
- iOS 使用 Songti SC；Web 按 Songti SC / STSong / SimSun / Noto Serif CJK SC / serif 回退；Android 使用系统 serif，中文实际字形取决于厂商字库，不能保证与参考图一致。
- 仅标题减轻字重，不用透明度或全局极细体模拟轻盈，确保小字及夜间正文可读。

排版层级：

| 层级 | 建议范围 |
|---|---:|
| 展示标题 | 32–40px |
| 页面标题 | 26–30px |
| 区块标题 | 18–20px |
| 正文 | 15–16px |
| 辅助文字 | 13–14px |
| 标签 | 12px |

规则：

- 标题以中等字重为主，避免过细或过粗。
- 长文本优先保证可读行宽和行高。
- 手机与 Web 保持相同的层级关系，桌面主要通过容器和留白建立层次，不同比放大所有文字。

### 4.4 间距、形状与层次

- 使用 4px 基础网格。
- 常用间距包括 8、12、16、20、24、32、40、48、64px。
- 不强制所有值必须是 8 的倍数。
- 普通控件圆角为 10–12px。
- 普通卡片圆角为 16–20px。
- 胶囊形仅用于标签或少量适合的主操作。
- 普通卡片默认无阴影或使用极弱阴影。
- 明显阴影仅用于浮层、对话框和确有悬浮语义的内容。
- 页面优先使用留白分组，不为每一块内容都增加卡片。

### 4.5 动效

- 按钮反馈：120–180ms。
- 小型状态切换：180–240ms。
- 页面与浮层进入：240–320ms。
- 常规过渡使用淡入和 4–12px 的轻微位移。
- 角色呼吸和背景漂浮可保留慢速循环。
- 避免大幅弹跳、长时间阻塞操作的过渡和无意义循环。
- 尊重系统减少动态效果，并兼容现有降低透明度设置。
- 不使用“低于某个时长即为问题”的机械替换规则。

## 5. 响应式框架

项目继续使用 Expo、React Native 和 React Native Web 的单代码库。业务逻辑、接口、状态、设计 token 和基础组件共用；只有布局确实不同时才拆分平台展示组件。

### 5.1 目标尺寸

- 手机精细目标：375、390、414、430px。
- 平板兼容范围：768–1024px。
- Web 精细目标：1280、1440、1920px。
- 320px 手机保证基本可用，但不作为精细视觉目标。

断点必须集中定义，页面不得自行发明互相冲突的宽度判断。

### 5.2 手机

- 使用底部四项主导航。
- 页面使用单列布局。
- 常规水平安全留白为 20px，可由页面类型在统一规则内调整。
- 全屏任务页隐藏底部导航并使用顶部返回操作。
- 浮层优先使用底部抽屉。

### 5.3 平板

- 不维护独立的第三套页面。
- 窄平板沿用底部导航，宽平板切换左侧导航。
- 内容限宽，避免表单和文字横向拉长。
- 只有内容关系适合时才使用双栏。

### 5.4 Web

- 使用约 88–104px 的左侧窄导航栏。
- 导航入口与手机一致，以图标和短标签呈现。
- 当前导航项使用浅强调背景，不使用强烈发光。
- 主内容最大宽度根据页面类型控制在 960–1280px。
- 陪伴、个人资料等页面使用居中主区域。
- 信箱使用列表与详情双栏。
- 场景主页使用响应式卡片网格。
- 场景播放可充分使用导航之外的剩余空间。
- 手机 Bottom Sheet 在桌面对应居中 Dialog 或右侧面板，内容组件共用。
- 所有可操作元素具有鼠标悬停、键盘焦点、点击和禁用反馈。

### 5.5 代码组织

默认使用同一展示组件配合响应式样式。只有布局结构显著不同的页面才使用：

```text
页面容器
├─ 数据与业务状态
└─ 展示布局
   ├─ MobileLayout
   └─ DesktopLayout
```

手机与桌面布局不得复制接口请求、业务操作或状态管理。

## 6. 组件体系

组件以真实页面需求为边界，不创建难以维护的万能组件。

### 6.1 全局框架

- `AppShell`：页面背景、导航、安全区和桌面内容区。
- `SideNav`：Web 与宽平板左侧导航。
- `BottomNav`：手机与窄平板底部导航。
- `PageContainer`：页面最大宽度和统一留白。
- `PageHeader`：标题、说明、返回和右侧操作。

### 6.2 基础控件

- `Button`：主要、次要、文字、危险样式，支持常规和紧凑尺寸。
- `IconButton`：统一图标尺寸、点击区域和交互状态。
- `TextField`、`TextArea`：默认、聚焦、错误、禁用和占位状态。
- `Card`：基础、可交互、强调三种明确变体。
- `ListItem`：设置、信箱条目和选择列表的通用结构。
- `Chip`：状态、标签和轻量筛选。
- `Divider`
- `EmptyState`
- `LoadingState`
- `Toast`
- `Dialog`
- `BottomSheet`

### 6.3 业务组件

- `CompanionAvatar`
- `MessageBubble`
- `LetterCard`
- `SceneCard`
- `PreferenceRow`
- `MemoryCard`
- `AudioControl`

### 6.4 组件规则

- Token 表达设计语义，不追求替换所有数字。
- 页面不得重复实现通用按钮、输入、弹窗和导航。
- 所有交互组件覆盖触摸、悬停、键盘焦点和禁用状态。
- `Dialog` 与 `BottomSheet` 可以共享内容，但保留符合平台的容器交互。
- 现有 `design-components.tsx` 不是默认完成品；可复用部分保留，职责重叠或错误的部分简化、合并或替换。
- 特殊场景无法合理使用通用组件时，允许页面专用实现，不扩张通用组件 API。

## 7. 页面分组与设计重点

### 7.1 陪伴模块

覆盖：

- `CompanionIdle`
- `CompanionChat`
- `ModeSheet`
- `VoiceCall`
- `SleepDump`
- `ProcessingScreen`
- `ReceiptScreen`

重点：

- 作为第一组完整跨端样板。
- 手机保持沉浸式单列体验。
- Web 使用居中限宽主舞台。
- 统一角色、消息、输入、语音和模式选择。
- 在本组中验证全局动效节奏。

### 7.2 登录与引导

覆盖登录、注册及四步新手引导。

重点：

- 保留步骤、功能和文案。
- 手机使用单列流程。
- Web 使用居中引导卡或克制的左右布局。
- 统一表单、步骤反馈和伙伴选择状态。

### 7.3 信箱

覆盖：

- `MailboxScreen`
- `TaskDetail`
- `StorageDetail`

重点：

- 手机使用列表进入详情。
- Web 使用左侧列表与右侧详情双栏。
- 统一信件、任务和收纳内容的层级。
- 完整覆盖空、加载、错误和选中状态。

### 7.4 场景

覆盖：

- `SceneScreen`
- 场景创建与角色设置流程
- `ScenePlay`
- `SceneEnd`
- 现有 3D 与剧场内容

重点：

- 不机械替换素材色和图片蒙层。
- 手机使用纵向浏览和沉浸播放。
- Web 使用响应式场景网格和充分利用空间的播放区。
- 普通应用界面与沉浸场景允许不同层次，但共用基础交互规范。
- 不修改场景逻辑、剧场数据和操作流程。

### 7.5 个人资料与记忆

覆盖：

- `ProfileScreen`
- `PetChange`
- `PetHandoff`
- `MemoryScreen`
- `MemoryReviewScreen`

重点：

- 统一设置项、开关、选择器和信息卡。
- Web 使用限宽设置面板，内容合适时分栏。
- 保留夜间模式入口。

## 9. 迁移规则

### 9.1 新旧体系

- 新体系是唯一目标。
- 旧 `theme.ts` 在迁移期作为兼容层保留。
- 新迁移组件不得继续引入旧零散常量。
- 每完成一个页面组，移除该组对旧体系的依赖。
- 全部迁移完成且确认无引用后，才删除旧实现。

### 9.2 样式分类

每个旧样式必须先判断语义：

- 通用语义进入主题或公共组件。
- 页面布局保留在页面内，但服从统一断点和间距规则。
- 业务状态色使用明确状态 token。
- 素材、场景和图片蒙层允许保留页面专用值。
- 相同语义重复三次以上时考虑抽取。
- 数值相同但用途不同的样式不得仅因数值相同而合并。

### 9.3 禁止事项

- 禁止全局机械替换颜色、间距或动画时长。
- 禁止在视觉任务中顺带修改接口、文案或业务流程。
- 禁止为通过统计而把合理的素材值改成含义错误的 token。
- 禁止生成 `.bak` 文件污染仓库。
- 禁止在一个任务未验证时提前迁移下一组页面。

## 10. 单任务工作流

每一项实施任务遵循：

1. 完整读取目标文件和直接依赖。
2. 记录修改前状态和现存错误。
3. 明确允许修改的文件范围。
4. 只实现当前任务。
5. 运行 TypeScript 编译。
6. 运行目标页面并检查控制台。
7. 检查指定手机和 Web 尺寸。
8. 验证点击、输入、返回、切换等主要交互。
9. 检查日间视觉及夜间基本可用性。
10. 汇报修改、文件、验证结果和遗留问题。
11. 经用户确认后进入下一项。

每项交付只需清楚说明：

- 做了什么。
- 修改了哪些文件。
- 如何验证，结果是什么。
- 下一项是什么。

## 11. 验收要求

### 11.1 每个页面组

- TypeScript 编译通过。
- 手机 375、390、430px 无关键布局问题。
- Web 1280、1440、1920px 无关键布局问题。
- 核心流程无业务回归。
- 日间视觉符合本文。
- 夜间无严重可读性或操作问题。

## 13. 决策摘要

- 视觉方向：温暖、安静、疗愈。
- 平台优先级：手机与 Web 同等重要。
- 技术结构：单代码库，共享业务和设计基础，布局按需分离。
- 改动幅度：中度优化，保留功能、文案和页面结构。
- 素材策略：保留现有素材。
- 主题策略：日间精细设计，夜间入口保留并保证基本可用。

- 手机导航：底部导航。
- 动效：克制、柔和。
- 推进方式：设计基础先行，陪伴模块作为首个完整样板，逐组验证和确认。

## 14. 已实施记录（2026-07-25 · 分支 `refactor/frontend-visual-v2`）

以下设计与交互原则已在本文指导下实施并提交，后续开发应保持一致性。

### 14.1 强调色统一

日间模式的通用交互强调色已统一为暖金体系：

- `accent: "#B8860B"`（暖金棕）— 用于文字、图标、焦点等前景强调
- `accentSurface: "#F6E7A8"`（奶油鹅黄）— 用于按钮实底、选中背景等承载面
- `textOnAccent: "#4B463F"` — accentSurface 上的文字前景
- 底部导航和侧栏的选中态使用此体系，不再使用砖红或暗红

**规则**：新组件和页面迁移使用 `theme.colors.accent` / `accentSurface` / `textOnAccent`，不自行定义强调色。

### 14.2 玻璃质感（GlassSurface）

关键半透明面板使用 `BlurView`（expo-blur）叠加暖色半透明层，逼近 Proto 的 glass morphism 效果。

- `GlassSurface` 组件位于 `design-system/components/effects.tsx`
- 已应用于：底部导航栏、陪伴首页输入框、聊天输入框
- **规则**：页面级输入区域优先使用 `GlassSurface`，不自行拼接模糊与半透明
- **约束**：low intensity (8–12) + 半透明色叠加，避免 Android 模糊性能问题

### 14.3 纸张纹理（GrainTexture）

卡片可叠加微弱 SVG 噪点纹理，营造"纸质感"。

- `GrainTexture` 组件位于 `design-system/components/effects.tsx`
- `Card` 组件的 `grainy` prop 可直接启用
- 已应用于：珍藏卡（KeepsakeArtifact）、信纸（LetterPaper）
- **规则**：珍藏、信纸、结算卡等"值得停留"的内容卡片应启用 grain
- **约束**：受 reduced motion / reduce transparency 设置控制，性能开销极低

### 14.4 Card 变体

`Card` 组件正式支持三种变体：

| 变体 | 用途 |
|---|---|
| `default` | 普通内容容器，白底无阴影 |
| `elevated` | 重要卡片，白底 + 极弱阴影 |
| `emphasized` | 强调卡片，暖背景（替代旧 `emphasized` prop） |

### 14.5 片场角色设定 — 单页对话式

角色设定从三步填表（名字→描述→traits 确认）改为单页对话式：

- 姓名 + 关系 + 描述 + 可选补充在同一页面
- 行为倾向（traits）静默请求后端，不阻塞进入
- 移除了渐入动画 traits 列表和等待步骤
- 保留 `adjusted` 字段作为可选"还有什么想补充的"输入

### 14.6 片场演绎体验

- **字幕渐变透明度**：从 90% 减至 55%，让 3D 剧场背景更可见
- **"TA 不太像"常驻**：演绎中顶部栏始终显示校准入口，无需暂停
- **"自己说"视觉权重**：从虚线幽灵按钮提升为与预设选项同等的实底选项

## 15. 登录与片场视觉收敛（2026-09-11）

针对登录和片场装饰多于内容的问题，本节优先于这些页面的历史装饰方案；不改变业务接口、输入数据、创建步骤或素材语义。

- 登录/注册采用安静的账号入口：手机单列、桌面介绍与表单双列，取消悬浮表单外框及卖点图标块，保留原有文案和登录逻辑。
- 片场内置场景采用横排标题、简短描述和明确进入入口。手机纵向列表、桌面可换行卡片网格；所有卡片直接可选，不依赖轮播居中。取消竖排金字、光斑渐变及装饰性缩放。
- 场景创建采用主题背景、公共输入组件和克制的选择态。浅色步骤栏取消幕布花边，实际搭建状态的深色演出视觉不在本轮调整范围。
- 讲述、整理预览、角色设定的内容区最大宽度为 720；非桌面视口预留底部导航空间，长内容可滚动。
- 公共 PageHeader 使用系统无衬线字体，与当前项目字体约束保持一致。
- 本轮未进行截图或真机视觉验收，按用户要求由用户手动检查；不能以类型检查代替视觉验收。

# 米露全 App 轻量伙伴系统设计

## 1. 目标

第一阶段用有限的美术资源，让米露成为贯穿主 App 的核心伙伴。覆盖 Web 和 Android，优先保证陪伴首页与聊天页体验完整，信箱、片场和“我的”页面只提供轻量、明确的场景反馈。

本方案以“一个静态母图 + 已有舔爪视频 + 五个新增视频”为资源上限，不建设完整桌宠引擎。

## 2. 范围收敛

第一阶段不实现：

- 多落点随机移动。
- 自由寻路、碰撞和动态避障。
- 跨页面连续移动和动作状态继承。
- 复杂全局行为状态机和动作队列。
- AI 情绪判断和 AI 动作决策。
- 拖拽、养成、亲密度和动作解锁。
- 自动声音和 iOS 专项适配。
- 单独的难过、回头、待机呼吸和睡觉循环视频。

每个页面只有一个固定安全位置。米露不能遮挡输入框、导航、内容主体和关键按钮。

## 3. 动作资源

### 3.1 真实视频动作

| 动作 ID | 来源 | 用途 |
| --- | --- | --- |
| `groom` | 已有 | 日常舔爪和空闲生活感 |
| `walk` | 新生成 1 | 页面进场 |
| `listen` | 新生成 2 | 聊天、等待回复、阅读信件 |
| `sleep` | 新生成 3 | 趴下并进入睡眠 |
| `happy` | 新生成 4 | 点击、回复完成、操作成功 |
| `wake` | 新生成 5 | 伸懒腰并观察、恢复操作、新信到达 |

### 3.2 静态与代码动效

- 默认待机：正面静态母图。
- 轻微呼吸：静态图做低幅度缩放或位移。
- 睡眠持续状态：使用 `sleep` 最后一帧。
- 轻微难过：使用 `listen` 结束帧，降低动作频率，并显示温和文案。
- 普通等待：使用 `listen` 或静态待机，不新增视频。

## 4. 页面呈现

### 4.1 陪伴首页

- 米露位于页面视觉中心。
- 支持全部六个视频动作。
- 点击播放 `happy`。
- 每隔 15–30 秒可在 `groom` 和 `wake` 中随机播放一次。
- 长时间无操作播放 `sleep`，之后停在睡眠静态帧。
- 用户恢复操作播放 `wake`，然后回到待机。

### 4.2 聊天页

- 米露固定在顶部小型陪伴区。
- 用户输入或等待回复时播放 `listen`。
- 回复完成时播放 `happy`。
- 不自主行走，不进入消息滚动区和输入区。
- 负面表达不触发独立情绪视频，只保持安静倾听。

### 4.3 信箱页

- 米露固定在信箱旁边。
- 默认显示静态待机。
- 新信到达播放 `wake`。
- 打开信件后显示 `listen` 结束姿势。
- 不在列表区域移动，不播放随机动作。

### 4.4 片场页

- 米露固定在舞台或生成区域边缘。
- 生成过程中播放或停留在 `listen`。
- 生成成功播放 `happy`。
- 生成失败保持安静坐姿，并显示温和文案。
- 不进入场景预览和编辑控件。

### 4.5 “我的”页面

- 米露固定在个人信息区下方。
- 默认显示静态待机。
- 每隔 20–40 秒可播放一次 `groom`。
- 长时间停留播放 `sleep`。
- 不使用走路和频繁业务反馈。

## 5. 轻量触发模型

页面只使用以下事件：

```text
PAGE_ENTER
PET_TAPPED
WAITING_STARTED
ACTION_SUCCEEDED
USER_IDLE
USER_RESUMED
NEW_LETTER
```

映射规则：

```text
PAGE_ENTER       → 可选 walk → idle
PET_TAPPED       → happy → idle
WAITING_STARTED  → listen → listen-pose
ACTION_SUCCEEDED → happy → idle
USER_IDLE        → sleep → sleeping-pose
USER_RESUMED     → wake → idle
NEW_LETTER       → wake → idle
```

同一时间只播放一个动作。新事件不会排成长队，只允许覆盖一个尚未开始的待处理动作。页面离开或 App 进入后台时立即停止播放并清理计时器。

## 6. 技术结构

只建设三个模块：

1. `MiroAssetRegistry`：记录六个动作在 Web 和 Android 上的资源、帧率、时长、循环方式与结束静态帧。
2. `MiroPlayer`：接收动作 ID，负责加载、播放、结束回调、失败回退和减少动态效果。
3. 页面适配器：为每个页面提供固定位置，并把有限业务事件映射为动作 ID。

播放器只维护：

```text
currentAction
isPlaying
fallbackPose
randomIdleEnabled
```

Web 每个动作使用精灵图和 CSS 动画。Android 使用压缩帧序列。两端共用动作 ID 和事件映射，不要求共用底层播放实现。

## 7. 性能与降级

- 首屏只加载待机图和当前页面即将使用的动作。
- 其他动作在页面稳定后按需加载。
- Web 不逐帧更新 React 状态。
- Android 不同时常驻全部动作帧。
- 动作加载失败时回到对应静态姿势。
- `walk` 失败时直接显示在固定位置。
- 全部米露资源失败时回退到 `PetPlaceholder`。
- 开启减少动态效果时只显示静态姿势和短文案。
- 米露异常不能阻塞任何业务功能。

## 8. 验收标准

- 六个动作在 Web 和 Android 均能完整播放。
- 五类页面各有一个固定安全位置，米露不遮挡操作。
- 陪伴首页具备点击、随机空闲、睡眠与唤醒体验。
- 聊天页具备倾听和回复完成反馈。
- 信箱、片场和“我的”页面按明确事件提供轻量反馈。
- 动作之间无明显跳位、黑边、透明残影和角色变形。
- 连续点击不会堆积动作。
- 页面切换与前后台切换后不存在重复计时器。
- 资源失败和减少动态效果路径能够安全回退。

## 9. 后续扩展

只有在轻量版本稳定且新增素材充足后，才单独评估多落点、自由移动、更多情绪动作、iOS 适配和养成系统。

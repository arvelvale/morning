# 米露 Web 舔爪动画精灵图优化设计

## 背景

陪伴首页的米露舔爪动画由 37 张 640×640 透明 PNG 组成，以 12 FPS 播放。当前 Web 实现每帧通过 React 状态更新替换图片，会反复触发组件渲染和浏览器图片处理，导致电脑网页预览偶发掉帧。

## 目标

- Web 端舔爪动画播放稳定、连续，无明显掉帧。
- 保持现有画面、12 FPS、5–12 秒随机触发间隔和首页布局不变。
- 保留减少动态效果、页面进入后台暂停和资源失败回退。
- iOS、Android 暂时保留现有逐帧 PNG 实现，避免扩大修改范围。

## 方案

将 37 帧按单行或受浏览器纹理尺寸限制的规则合成为一张透明 PNG 精灵图，并为 Web 端增加专用渲染分支：

1. 精灵图只加载和解码一次。
2. Web 动画使用 CSS `background-position` 配合 `steps(36, end)` 播放完整序列，不再逐帧更新 React 状态。
3. React 只负责在静止状态和舔爪状态之间切换，并在一次动画结束后重新安排随机等待时间。
4. 原生端继续使用现有 `Image` 逐帧逻辑。

为避免超宽单行图片超过部分 GPU 的纹理限制，精灵图采用网格布局。每格保持 640×640，组件根据帧号生成对应的关键帧位置；显示区域继续按现有 `contain` 视觉尺寸缩放。

## 组件边界

- `assets/pets/miro/groom/`：保留原始帧，供原生端使用。
- 新增 Web 精灵图资源：由现有 37 帧确定性生成。
- `src/pets/assets.ts`：登记精灵图、帧数、帧尺寸和帧率。
- `HomePetArtwork.tsx`：按平台选择 Web 精灵图或原生逐帧实现。
- Web 样式：声明一次性舔爪关键帧动画；动画结束后回到静止图。

## 失败与无障碍处理

- 精灵图加载失败时回退到静止图片，不显示破损资源。
- 系统启用“减少动态效果”时只显示静止图片。
- 页面转入后台时停止动画，恢复前台后重新从静止等待开始。
- 不改变图片的点击穿透和辅助功能设置。

## 验收标准

- 在 `http://localhost:8081/?screen=companion` 的电脑网页预览中，连续观察至少三次舔爪动作，无明显停顿或跳帧。
- 动画期间不发生每帧 React 状态更新。
- 米露静止与舔爪画面的位置、大小和透明背景保持一致。
- TypeScript 检查和现有前端测试通过。
- 原生端仍引用原始逐帧资源，不受 Web 优化影响。

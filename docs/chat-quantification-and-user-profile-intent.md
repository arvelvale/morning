## 一、意图（一句话）

让喵灵从「每次整理一次」进化到「持续理解用户」：
把用户**日常聊天的内容**（不止情绪）量化成结构化信号，并沉淀为一份**长期稳定、跨时间的用户画像**，
使「整理思绪」和「主动陪伴」越来越懂用户，而不是每次都从零开始。

## 二、背景

**喵灵（Morning）现状**：
- 已有「睡前倾倒」自动分类：一段话 → extractor（LLM）拆成 待办 / 想法 / 情绪 / 片段，落双轴记忆（layer × depth）。
- 已有场景重演（把「没闭环的过去」变成 3D 场景）、桌宠来信（喵灵主动）。
- 记忆有 `profile` 层概念，但**没有系统化的用户画像**。

**缺口**：
1. **日常聊天没有被量化**。只有「睡前倾倒」这一个入口走内容分类；普通对话、语音通话里的内容，说了就过去了，没有沉淀成结构化的东西。
2. **没有长期用户画像**。喵灵知道用户「这次」说了什么，但不知道用户「长期」在乎什么、什么反复困扰 TA、适合怎么陪伴。整理和主动都缺「对用户的持续理解」。

## 三、要达成什么

### 3.1 量化日常聊天内容

从用户**所有**聊天来源（对话、语音转写、睡前倾倒、片场对话等）持续提取**内容维度的结构化信号**。重点是内容，不是情绪：

- **话题 / 主题**：这段聊了什么。
- **实体**：涉及的人、物、事、地方。
- **意图类型**：想法 / 待办 / 倾诉 / 想重演的过去 / 提问 / 其他。
- **关键事件与状态**：发生了什么、某个事情的进展/变化。
- **重复模式**：反复出现的困扰、常提到的人、反复做/想做的事。
- 情绪维度可以作为补充信号，但不是主角。

一句话：**用户每天说的话，沉淀成一张「这段时间在发生什么、什么在反复出现」的结构化视图。**

### 3.2 用户画像层

把量化结果沉淀为**长期稳定、跨时间的认知**——不是逐条记忆的堆叠，而是收敛出的稳定结论：

- 用户在乎什么、长期偏好、重要关系。
- 反复出现的困扰、习惯模式、情绪低谷/高峰的规律（如果有）。
- 陪伴偏好：喜欢故事还是直接提醒、适合的触达时机与方式。
- 成长轨迹：想重演的过去、正在经历的改变、达成的事。

画像要**可被用户看到、可被用户纠正**——它不是秘密档案，是「喵灵对用户的理解，用户有权修正」。

### 3.3 画像驱动行为（终点）

画像不是存着看的，要能影响实际行为：

- **整理思绪时**：用画像让分类、复述更贴用户（例如知道 TA 反复提某个人，整理时更能抓住重点）。
- **主动陪伴时**：用画像决定「说什么、何时说、怎么说」——贴当前状态、不打扰。
- **场景重演时**：画像帮助理解「为什么这个过去放不下」，让重演更有意义。

## 四、设计空间（执行者自由决定）

以下都交给你设计，不预设答案：

- 内容量化的维度、字段、粒度。
- 画像的存储形态（文件 / 表 / 分层结构 / 混合）与更新策略。
- 与现有 memory 系统如何分层或衔接（可参考栖光思路，也可自创更合适的）。
- 提取时机：实时 / 批处理 / 夜间合并 / 混合。
- 用什么模型、怎么调：可全 LLM，可词典 + LLM 结合，可分层路由。
- 量化的「热度 / 权重」如何随时间衰减或强化。
- 用户纠正画像的交互与反馈闭环。

只要不违背「意图」和「边界」，方案越贴合喵灵现状越好。

## 五、边界（少而重要）

1. **伦理**：不诊断、不贴人格标签、不把推测当事实；对用户说任何关于 TA 的话，都要是「观察 + 邀请确认」而非断言。
2. **隐私**：核心 / 脆弱类内容遵循已有隐私规则，不外发。
3. **兼容**：不破坏现有场景重演、桌宠来信、睡前倾倒链路；新能力可增量接入、可独立开关。
4. **表达**：面向用户的画像相关内容，文案要温和、第一人称、可被纠正，符合喵灵整体的治愈调性。

## 六、验收（期望看到的结果形态）

- 一段日常聊天（或一批聊天记录）能被量化成结构化的内容信号——可以演示、可以看到结果。
- 多段 / 一段时间聊天后，能沉淀出一份**稳定、贴用户、可读**的用户画像。
- 画像确实驱动了至少一处实际行为（整理变准 / 主动来信变贴 / 场景更有意义），不是存了不用。
- 有用户查看 / 纠正画像的入口。

## 背景与 Why

用户希望模型利用现有零件库，自行组合想要经历或过去在意的场景。当前有 63 种注册零件，架构已经采用「模型描述物件关系，前端计算坐标」。本次目标是让这些关系可靠地出现在画面中，减少坐空、物件落地、道具脱手和主体出画。

规格正本：[关系式布局规格](../specs/2026-08-27-scene-relational-layout.md)。本文件维护修复顺序、工作项和验收证据；长期契约变更更新规格正本。

### 当前真实链路

用户设定 → `SceneScreen.buildScene` → `POST /api/v1/scenes` → 生成剧情开场 → 地点关键词筛零件 → 模型生成 SemanticSceneSpec → 后端清洗 → 存入 `scenes.scene_spec` → `assembleAnySpec` → `solveLayout` → `runChecks` → `assembleScene` → Three.js 渲染。

当前用户入口使用非流式创建。3D 规格生成失败后会尝试图片场景。存量绝对坐标规格直接渲染，不经过关系解算。

## 目标与非目标

目标：关系正确、结果可复现、失败可定位、手机和桌面构图可用、模型参数有明确预算。保留已有场景选择、人物设定、剧情推进和用户数据隔离。

本轮不引入通用物理引擎、不更换 Three.js、不扩展自由生成模型资产、不自动重写存量场景、不部署服务或发布 APK。先交付计划，再沿本计划实施；代码修复已获用户授权，无需另行重复确认。

## 关键设计决策

### 1. 几何布局以关系图为依据

- 按 ID 建索引后，对所有物件先测量；人物使用人物系统提供的接触锚点，不依赖物件 box 分支。
- `on/in/sitOn/heldBy` 是硬约束（必须满足的关系）；`nextTo/near/inFrontOf/behind` 是软约束（可在限定范围内调整）。承载和方向分别保留，不以遍历顺序静默覆盖冲突字段。
- 宿主无自己的承载关系时也必须先定位；heldBy 的人物依赖纳入排序。互相 facing 不作为位置依赖，避免正常对视形成布局环。
- 硬约束成环、无效引用和不可用锚点必须报告。软关系环用稳定顺序求解并检查残差。
- 按宿主分配固定 seatIndex；座位不足显式降级并报告，不能用取模把第三个人放回第一人的座位。
- 顺序为：归一化/测量 → 依赖定位 → 软关系与碰撞处理 → 边界处理 → 朝向 → 最终锚点重放 → 验收 → 相机。
- 推动宿主时承载子树一起移动；重放后再检查，防止修复过程中重新穿模。所有迭代均有上限。
- 持物初始位置取姿态对应手部锚点；动态姿态使用人物层级的实际手部挂点随帧跟随。对象挂接需检查缩放和释放所有权。

### 2. 校验目标是满足场景原意

新增结构化 issue：`code / objectIds / severity / status / expected / actual`；区分 repaired、unresolved、degraded。已有报告 UI 在迁移时保留兼容映射。

检查座面接触、物件承载面内包含、手部挂点距离、朝向误差、软关系偏差和镜头可见性。不能把「残余穿模待观察」计为已修复。`n.degraded` 必须进入报告。

几何碰撞使用独立 X/Z 范围和 Y 高度，考虑旋转与局部包围盒中心；承载父子、容器和背景有明确豁免。首阶段用变换后的 AABB（轴对齐包围盒）；复杂旋转误报经夹具证明后才引入更复杂算法。

### 3. 统一零件契约，再做组合模板

- 前端零件声明维护 type、用途、分类、允许参数、范围、支持的锚点/关系、预算与版本。
- 从声明导出后端可读目录，并通过检查防止导出漂移；不在 Python 复制几何实现。
- 基于 place + plot + 显式关键物件选候选，先用目录标签/别名检索；未知地点可扩宽候选，不强制新模型调用。
- few-shot 必须使用本次候选允许的物件。清洗检查实际候选范围、数组类型、有限数值、ID/引用类型、冲突关系；不得因错误数据形态抛出未处理异常。
- 按组件限定尺寸、数量、字符串长度及粒子参数；全场景增加对象/粒子等预算。预算数值在移动端基线测量后定稿，不能仅限制 props 数量。
- 第二阶段引入可复用小组合：桌边交谈、长椅并坐、站台送别。组合只约束摆放，人物、信物和背景保留可选；自由组合入口继续可用。
- 模型产物先做结构校验和确定性修复。若需模型修复最多一次且共享总时间预算；不默认开启无限评审循环。

### 4. 相机只有一套最终求解

先完成布局，再用真实 aspect/FOV 和主体包围盒求机位，最后投影复核。显式指定关键人物/信物优先级，其他大件不应无限拉远镜头；旧规格的显式机位继续保留。

手机、桌面均检查人物头脚和关键物件可见性；画面边缘保留约 10% 安全区（NDC 范围 [-0.8,0.8]，整幅宽度为 2），遮挡单独评估，不以「中心点入画」代替完整可见。

### 5. 确定性、版本与性能

- 规范化规格计算 seed，按对象 ID 派生随机数；几何构造与测量使用相同随机源。
- 缓存键包含零件参数、种子、资产/布局版本。测量代理资源明确释放；共享材质不可随代理体销毁。
- 预览报告直接复用实际解算结果，不为报告额外拼装一整个场景。
- 语义规格增加版本信息；兼容缺省版本。旧绝对坐标场景不迁移；语义场景随引擎更新可能变化，应保留版本回放或显式升级策略，并验证后再发布。
- 先记录开场/规格/图片兜底耗时、调用次数与客户端首帧时间，再优化串行等待。独立生成可受控并发，但需共享上游限流和总时间预算。
- 先展示可验证的阶段进度；持久化任务 ID、重进恢复及幂等作为后续切片。若落库新任务状态，必须同步迁移；不把临时进程任务说成可恢复任务。

## 验收标准

1. 桌杯顺序交换不改变关系满足情况；坐姿臀部与座面接触误差目标 ≤0.05m（按人物比例缩放），初始手部挂点误差目标 ≤0.05m，实际美术几何标定后固化容差。
2. 同座具不同人物使用不同可用槽；超员明确降级。链式承载旋转、移动、碰撞后仍成立。
3. 人物移动/转向/动作动画中，指定手持物跟随；报告不会把无法满足的关系记为成功。
4. 未知零件、错类型数组、自引用、环引用、非有限数值、负粒子数量和极大尺寸不会使整场景崩溃或无限分配资源。
5. 原有绝对坐标样例可渲染；关系夹具、至少一批真实模型生成样例跨手机/桌面视口验收。用例应覆盖家中交谈、公交站、乡村、雨夜持伞和站台。
6. 同版本/同 seed 输出稳定；几何测量与实际构造一致。记录变化前后的时延、draw calls、三角形/粒子量和内存趋势，不预先承诺提速比例。
7. 执行前端 typecheck、专用布局回归、后端清洗测试、git diff --check；编译/纯函数通过与浏览器/真机通过分别记录。

### 2026-09-07 · S2 数值/动态验收

**完成范围**：实际坐姿接触、7 类专用握点、完整原始关系的降级追踪、旋转承载范围/容器高度/软关系/朝向残差、承载子树推挤及动画挂接。相机复核只报告最终机位的保守预检，不再把平移 look 当成已修复；真实视口构图仍属 S4。

原因 → 修改 → 原始复现验证：

- 雨伞原点就是握柄，过去重新按包围盒中心挂接导致脱手。改用 `grips.ts` 的具名握点：手机、雨伞、书、茶杯、背包、行李箱、相框；雨伞/杯/包类保持直立，其他件随手旋转。一只右手只接一个物件，其余或无专用握点的零件降级到身旁并报告，不静默叠在一起。
- 固定坐姿高度无法对应真实腿部/衣服。改为实测接触网格；语义就坐使用水平接触腿段，裙装折叠到膝部，老人前倾时膝部裙摆保持水平；呼吸不再改变接触高度。初次射线测试发现成人裙装悬空约 0.185m，修复后在同一 0.05m×人物比例阈值下通过；没有放宽阈值。
- 呼吸引入非均匀缩放，直接分解的四元数可能非单位长度。挂接统一归一化旋转并抵消人物缩放；手动写矩阵后显式标记世界矩阵需更新，避免首帧/本帧挂点失效。
- 推挤以承载子树为单位，末尾重放硬约束；装配器保留物件承载父子关系，使书上手机等组合随手运动。只读终检不会重新钳位、贴地而拆散已满足的关系。
- 逐条对照原始请求与实际保留关系，每个被忽略的冲突/无效引用均有结构化记录。碰撞、测量/构造失败、超承载范围、容器高度、朝向与软关系残差均走统一报告；`repaired` 仅表示已执行的修正，最终残差以 `unresolved` 另列。

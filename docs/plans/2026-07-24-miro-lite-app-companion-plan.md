# 米露全 App 轻量伙伴系统执行计划

## 目标

以现有舔爪动画和五个新增动作视频为上限，在 Web 与 Android 中完成可复用的米露播放器，并将米露以固定安全位置接入陪伴首页、聊天、信箱、片场和“我的”页面。

## 阶段 0：素材定稿

### 任务

1. 保存三张高清角色参考图：
   - 正面坐姿。
   - 四分之三站姿。
   - 完整左侧面站姿。
2. 按顺序生成五个新视频：
   - `walk`。
   - `listen`。
   - `happy`。
   - `sleep`。
   - `wake`。
3. 每个动作只选择一个正式版本。
4. 检查角色一致性、四肢结构、尾巴、画面漂移和首尾姿势。
5. 将正式原视频放入素材源目录，保留原始文件，不直接作为运行时资源。

### 完成标准

- 六个动作的视觉形象一致。
- 每个视频角色完整、镜头固定、背景便于去除。
- `walk` 可循环；其余动作有明确开始与结束姿势。

## 阶段 1：素材加工与注册表

### 任务

1. 为六个动作去除背景并清理透明边缘。
2. 统一画布、角色锚点、显示比例和裁切边界。
3. Web 输出每个动作的透明精灵图。
4. Android 输出压缩后的透明帧序列。
5. 从 `sleep`、`listen` 等动作提取结束静态帧。
6. 建立 `MiroAssetRegistry`，登记：
   - 动作 ID。
   - 平台资源。
   - 帧率和时长。
   - 是否循环。
   - 默认结束姿势。

### 完成标准

- 动作切换时角色位置不跳动。
- Web 和 Android 使用相同动作 ID。
- 单个动作资源失败不影响其他动作。

## 阶段 2：轻量播放器

### 任务

1. 新建 `MiroPlayer` 公共组件。
2. 支持 `play(actionId)`。
3. 支持动作结束回到指定静态姿势。
4. 同一时间只播放一个动作。
5. 只保留一个尚未开始的待处理动作。
6. 页面离开和 App 进入后台时停止动画并清理计时器。
7. 支持减少动态效果。
8. 支持资源失败回退到静态米露或 `PetPlaceholder`。
9. Web 使用精灵图和 CSS 动画。
10. Android 使用帧序列播放器。

### 完成标准

- 六个动作可以独立触发。
- 连续触发不会堆积或并发播放。
- 页面卸载后无遗留计时器。
- Web 动画不逐帧触发 React 更新。

## 阶段 3：陪伴首页

### 任务

1. 用 `MiroPlayer` 替换现有首页专用播放逻辑。
2. 页面进入时可播放 `walk`，随后回到待机。
3. 点击米露播放 `happy`，设置点击冷却。
4. 每隔 15–30 秒在 `groom` 和 `wake` 中随机选择一次。
5. 长时间无操作播放 `sleep`。
6. 用户恢复操作时播放 `wake`。
7. 深浅主题下检查透明边缘和对比度。

### 完成标准

- 首页覆盖六个动作。
- 点击、随机空闲、睡眠和唤醒规则稳定。
- 动画不遮挡输入区和底部导航。

## 阶段 4：聊天页

### 任务

1. 在聊天顶部增加固定陪伴区。
2. 用户输入或等待回复时播放 `listen`。
3. 回复完成时播放 `happy`。
4. 负面内容不调用 AI 决定动作，只保持倾听姿势。
5. 聊天滚动和键盘弹出时保持安全位置。

### 完成标准

- 米露不进入消息滚动区和输入区。
- 倾听与回复反馈不会阻塞消息流程。
- 键盘显示时布局稳定。

## 阶段 5：信箱、片场和“我的”

### 信箱

- 固定在信箱旁。
- 新信到达播放 `wake`。
- 打开信件后停留在倾听姿势。

### 片场

- 固定在生成区域边缘。
- 生成中使用 `listen`。
- 成功使用 `happy`。
- 失败使用静态坐姿和温和文案。

### “我的”

- 固定在个人信息区下方。
- 20–40 秒可播放一次 `groom`。
- 长时间停留播放 `sleep`。

### 完成标准

- 三个页面均不遮挡关键操作。
- 只响应规定事件，不产生额外随机行为。
- 页面适配代码不复制播放器内部逻辑。

## 阶段 6：Web 与 Android 验收

### 功能测试

- 六动作逐个播放。
- 连续点击与重复业务事件。
- 页面快速切换。
- App 前后台切换。
- 减少动态效果。
- 单动作和全部资源加载失败。

### 视觉测试

- 五类页面的固定位置。
- 深浅主题。
- 不同屏幕尺寸。
- 动作切换锚点。
- 透明边缘、残影、裁切和闪烁。

### 性能测试

- Web 连续运行 30 分钟。
- Android 中低端设备内存占用。
- 页面反复切换后的计时器数量。
- 首屏资源加载时间。

### 完成标准

- 核心业务不受米露系统影响。
- Web 无明显掉帧。
- Android 无持续内存增长。
- 所有失败路径均能回退到静态形象。

## 推荐实施顺序

```text
walk 素材试制
→ 播放器最小原型
→ 其余四个视频
→ 素材批处理
→ 陪伴首页
→ 聊天页
→ 信箱/片场/我的
→ Web 与 Android 联合验收
```

先用 `walk` 验证角色一致性、去背景、精灵图、Android 帧序列和播放器链路。只有该链路通过后，才消耗剩余四次视频生成额度。

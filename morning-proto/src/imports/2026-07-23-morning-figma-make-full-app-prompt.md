# Morning 全套 App UI · Figma Make Prompt


请为 **Morning** 设计并生成一套完整、可交互的高保真 iOS App UI。

Morning 是一个以桌宠为入口的情感陪伴 Agent。它帮助用户自然聊天、在睡前倾倒并整理混乱思绪、接收 Agent 主动送来的内容，并把值得重新面对的经历转化为可选择、可互动的视觉小说式场景。产品不做心理诊断，不使用医疗化表达，也不通过红点、连续通知、亲密度损失或情感绑架制造留存。

### 一、设计目标

用户打开 App 时应立即感到：

- 轻盈、安心、被柔软地接住；
- 温暖但不甜腻，治愈但不幼稚；
- 有生命感，但不喧闹、不刺激；
- 像置身于一层正在缓慢流动的奶油晨雾。

请生成真正可点击、可切换、可演示核心流程的 App 原型，不要只生成静态概念稿。

### 二、平台与基础结构

- 平台：iOS；
- 基准画板：iPhone 393 × 852 pt；
- 遵守 iOS 顶部和底部安全区；
- 使用 SF Pro Display / SF Pro Text，中文使用 PingFang SC；
- 所有布局使用 Auto Layout；
- 建立颜色、字体、间距、圆角、阴影和动效 Variables；
- 建立可复用组件与 Variant，包括按钮、卡片、输入框、Tab、Bottom Sheet、Toast、状态标签和内容卡；
- 底部导航固定为四个 Tab：**陪伴 / 信箱 / 片场 / 我的**。

### 三、视觉方向：奶油晨雾

整体以低饱和、低对比、高明度的奶油色系为主。不要使用纯黑、大面积深色、高饱和绿色、荧光色、强烈紫色或明显的蓝绿医疗配色。

#### 日间颜色

- 页面底色：`#FFFBF3`；
- 奶油主色：`#F6E7A8`；
- 柔和奶黄：`#F9F0C8`；
- 淡杏辅助色：`#F3D8C7`；
- 薄荷雾绿：`#DDEDE3`；
- 雾蓝：`#DFE7F5`；
- 淡薰衣草：`#E9E4F3`；
- 主文字：`#4B463F`；
- 次级文字：`#847D72`；
- 极弱分隔：`rgba(91, 79, 62, 0.08)`。

#### 夜间颜色

夜间不要切换成黑色或深蓝色界面，而是让奶油晨雾进入“暖色黄昏”状态：

- 整体亮度比日间降低约 15%–20%；
- 背景使用暖灰米色、浅咖雾色、低亮度杏色和少量灰紫；
- 页面底色建议：`#E9E0D5`；
- 暖雾光：`#D9C4A9`；
- 夜间杏色：`#D8B8A7`；
- 夜间文字：`#4D4641`；
- 不使用纯黑背景，确保夜间不刺眼但仍然轻盈。

#### 流动渐变背景

参考超大柔焦色块叠加后的渐变效果，而不是普通的线性渐变：

- 每个页面背景由 3–5 个尺寸远大于卡片的柔和色团组成；
- 色团使用奶油黄、淡杏、薄荷雾绿、雾蓝和淡薰衣草；
- Layer Blur 使用 100–150；
- 色团边界必须完全消失，不能看见圆形轮廓；
- 中央内容区域保持较亮，彩色主要出现在边缘和页面纵深处；
- 不要加入大面积绿色滤镜；
- 可以加入 1%–2% 的细腻纸张颗粒，增强柔软与高级感，但不能看起来脏。

### 四、材质与空间

界面内容像半透明物体轻轻漂浮在奶油色柔光里。

- 卡片使用半透明暖白材质，透明度约 45%–70%；
- Backdrop Blur：24–40；
- 大型 Bottom Sheet 可使用 Blur 40–56；
- 卡片圆角：20–28；
- 小按钮和标签使用胶囊圆角；
- 边框尽量弱化，仅保留 `1px rgba(255,255,255,0.42)` 的高光边或极淡暖灰描边；
- 阴影使用暖灰棕，透明度不超过 8%–10%，例如 `0 12 40 rgba(121,100,72,0.08)`；
- 不要使用厚重玻璃拟态、强反光、霓虹描边或层层叠加的透明卡片；
- 页面依靠留白、明度差、模糊层级和轻阴影建立空间，不依靠粗边框；
- 底部导航和输入栏可以浮在内容上方，但不能遮挡重要信息。

### 五、排版与图标

- 大标题 26–30 pt，Medium，行高紧凑，字距约 `-0.02em`；
- 页面标题 22–24 pt；
- 卡片标题 16–18 pt，Medium；
- 正文 15–16 pt，行高 1.45–1.6；
- 辅助文字 12–13 pt，保持足够对比度；
- 文案整体简短、温柔、自然，不使用营销感和诊断感；
- 图标使用 1.5–1.75px 的圆润线性图标；
- 不使用彩色实心功能图标矩阵，不把首页设计成工具箱或 Dashboard。

### 六、桌宠区域

桌宠形象由其他设计师提供，本次不要设计具体角色。

- 使用清晰的角色占位组件 `Pet Artwork Placeholder`；
- 首页空闲状态为角色预留约 180–230 pt 的视觉中心区域；
- 角色占位必须支持替换透明 PNG、SVG 或动画资源；
- 不要给桌宠设计房间、家具或第三视角场景；
- 桌宠应直接面向用户，像存在于柔光空间中；
- 对话状态下角色缩小至约 72–96 pt，保留在聊天区域顶部或边缘；
- 角色不能退化为每条消息旁的普通头像；
- 界面的柔光可以轻微受到角色主色影响，但不能覆盖角色轮廓。

### 七、信息架构与完整页面

请设计以下完整页面和关键状态，并用 Prototype Connections 串联：

#### A. 首次使用

1. 品牌欢迎页：一句简短价值主张，不使用长篇功能介绍；
2. 陪伴方式说明：聊天、睡前清空、内容托管；
3. 选择主桌宠：使用角色占位卡，说明不同性格；
4. 主动陪伴与记忆授权：清楚说明可关闭、可删除、不过度通知；
5. 完成页：进入陪伴首页。

#### B. 陪伴 Tab

1. 首页空闲状态：
   - 桌宠是第一视觉焦点；
   - 顶部显示桌宠名称和一句轻量状态；
   - 中部不放永久功能卡；
   - 底部为自然语言输入框和模式入口；
   - 桌宠偶尔出现一句短气泡。
2. 对话状态：
   - 点击桌宠或输入框进入；
   - 桌宠缩小但不消失；
   - 聊天气泡保持轻量、留白充分；
   - Agent 单次回复 1–3 句。
3. 快捷模式 Bottom Sheet：
   - 自由聊聊；
   - 一股脑倒出来；
   - 说件放不下的事；
   - 回看一个片段。
4. 睡前倾倒输入页：
   - 支持长文本和语音输入；
   - 提示计划、担忧、灵感和情绪可以混在一起说；
   - Agent 在输入过程中不打断。
5. 思绪整理过程：
   - 用柔和光点或文字碎片缓慢归位表达整理；
   - 不做高速飞散或复杂数据动画。
6. 今晚托管回执：
   - 显示“今晚已替你接住 9 个念头”；
   - 展示明天要接住的事、值得留下的想法、被听见的感受和今晚无需处理的数量；
   - 突出一条时间事项；
   - 主按钮为“今晚到这里”；
   - 次按钮为“看看我替你放在哪里”。
7. 次日轻量邀请：
   - 提示昨晚有一个候选片段被留在草稿箱；
   - 提供“创建这个场景”“暂时不看”和删除入口；
   - 不使用强提醒和红色角标。

#### C. 信箱 Tab

信箱不是推荐信息流，应有清晰但轻盈的四个栏目：

1. **今日待启**：计划、提醒和最小行动；
2. **桌宠来信**：音乐、电影、书籍、问候、关系回访和场景邀请；
3. **三日寄存**：情绪、生活片段和未确认内容，显示柔和的剩余时间；
4. **长久珍藏**：用户主动留下的总结、灵感和重要记忆。

需要设计：

- 信箱总览；
- 今日待启卡和完成状态；
- 桌宠来信详情；
- 音乐、电影或书籍推荐卡；
- 三日寄存详情及“珍藏 / 放下”操作；
- 长久珍藏浏览页；
- 无来信、无待办和内容到期的空状态。

不要使用红色数字 Badge，只允许柔和暖黄色光点。

#### D. 片场 Tab

片场用于表达、探索和尝试不同回应，不声称修改记忆。

需要设计：

1. 片场首页：候选片段、草稿、已完成场景；
2. 候选片段详情；
3. 创建场景流程：
   - 补充人物；
   - 补充地点；
   - 简述经过；
   - 选择想尝试的表达或改变；
4. 场景准备页；
5. 视觉小说式场景体验页：
   - 氛围背景占位；
   - 角色立绘占位；
   - 底部对话区；
   - 2–3 个回应选择；
   - 安全退出入口；
6. 场景结束结算卡：
   - 展示用户尝试过的表达；
   - 提供保存、删除和再次体验；
   - 不给出心理诊断或正确答案。

高频场景模板：

- 没说出口的话；
- 冲突后的另一种回应；
- 重要时刻预演。

#### E. 我的 Tab

需要设计：

1. 当前主桌宠与伙伴列表；
2. 更换桌宠；
3. 桌宠交接信弹层：
   - 新桌宠说明旧桌宠告诉了它哪些粗粒度近况；
   - 不复述敏感细节；
4. 自定义桌宠入口，仅设计设置表单，不设计角色；
5. 主动陪伴频率设置；
6. 记忆管理；
7. 三日寄存规则；
8. 隐私与数据删除；
9. 主题与夜间氛围设置；
10. 字体大小、减少动态和减少透明度设置。

### 八、动效语言：颜色在呼吸

核心动效不是卡片上下漂浮，而是背景颜色非常缓慢地流动。

- 3–5 个大色团在 12–20 秒内移动约自身尺寸的 3%–6%；
- 同时只改变少量位置、透明度和尺度；
- 色彩变化幅度要小，用户不应明确意识到“背景在播放动画”；
- 页面静止时仍有细微生命感，但不能让人分心；
- 禁止快速循环、闪烁、粒子雨和大幅视差；
- 重要按钮按下立即缩放到 0.97，反馈 100–140ms；
- Tab 切换使用 180–220ms 的淡入和 4–8pt 位移；
- Bottom Sheet 使用 260–320ms、接近临界阻尼的弹簧，无明显弹跳；
- 页面进入和退出保持同一路径；
- 所有可触摸动效必须可中断；
- 场景选择和保存成功可使用一次非常轻的暖色光晕扩散；
- 不要让所有卡片持续上下浮动；
- 支持 Reduce Motion：关闭背景流动和位移，改为短暂透明度变化；
- 支持 Reduce Transparency：卡片改为更实的奶油白表面。

### 九、核心交互路径

请至少串联以下五条可点击演示路径：

1. 打开 App → 看见桌宠 → 点击桌宠 → 进入对话 → 收起对话；
2. 打开快捷模式 → 一股脑倒出来 → 整理过程 → 今晚托管回执；
3. 进入信箱 → 查看今日待启 → 完成一个待办 → 查看三日寄存；
4. 接收次日场景邀请 → 补充场景 → 进入互动剧情 → 获得结算卡；
5. 进入我的 → 更换伙伴 → 查看桌宠交接信 → 返回陪伴首页。

### 十一、禁止出现

- 不要设计成心理健康 Dashboard；
- 不要使用情绪分数、心率曲线、诊断标签或数据图表；
- 不要设计成普通 AI 聊天软件；
- 不要在首页排列大量快捷功能卡；
- 不要使用大面积深色、纯黑、高饱和绿、霓虹紫或蓝绿医疗色；
- 不要使用厚重边框、强阴影、强玻璃反光；
- 不要过度使用渐变文字；
- 不要生成具体桌宠形象；
- 不要使用房间、家具或第三视角桌宠场景；
- 不要使用红色数字角标、连续弹窗和强迫式提醒；
- 不要把情绪自动转化为任务；
- 不要擅自替用户永久保存敏感内容。

### 十二、最终交付

请在同一套文件中交付：

1. Foundations：颜色、字体、间距、圆角、阴影、模糊和动效规范；
2. Components：完整组件与 Variant；
3. Day Screens：全部日间页面；
4. Warm Night Screens：首页、对话、睡前倾倒和回执的暖色夜间版本；
5. Prototype：五条完整交互路径；
6. 页面标注：说明关键交互、内容生命周期和动效；
7. 保持所有页面视觉统一，并确保开发者可以直接理解和复用。

最终效果应该像一款真正可以长期使用的 iOS 情感陪伴产品：高明度、低饱和、奶油黄主导，半透明内容漂浮在缓慢流动的柔焦色光中；安静、柔软、有呼吸感，同时保持清晰、可信和可操作。

# Morning AI 片场 · Figma Make 修改 Prompt

请重新设计并修改当前 Morning App 的“片场”Tab。

保留当前 App 的奶油晨雾视觉系统、固定底部导航和其他三个 Tab，只重做“片场”及其进入后的完整交互流程。

当前片场是候选片段、草稿和已完成场景组成的普通卡片列表，构图过于简单，也不符合新的产品逻辑。请删除候选片段列表、草稿列表和已完成场景列表。

新的片场不是场景管理页，而是一个可以直接进入的 AI 角色扮演空间：

- 首页提供三个内置场景；
- 用户也可以通过语音口述创建自己的场景；
- 场景背景具有非常轻微的环境动效；
- 用户在场景中直接说话；
- Agent 扮演场景中的另一个人物，用语音、字幕和人物动作回应；
- 对方拥有半抽象人物形象，但不追求真实人物复刻；
- 对方性格由用户在进入场景前描述；
- 人物性格和敏感设定只用于当前场景；
- 退出后立即清除，不建立人物档案，不在不同场景之间复用；
- 用户不需要在片场首页看到已完成场景。

## 一、片场首页

### 顶部

标题：

“片场”

副标题：

“进入一个场景，试着说出不同的话。”

不要继续使用“重新走一遍”等暗示修改真实记忆的表达。

### 首页构图

不要使用纵向排列的相同白色大卡片。

将三个内置场景设计成横向滑动的“场景窗口”：

- 当前场景位于页面中央；
- 左右两侧露出相邻场景约 20–28pt；
- 让用户自然理解可以滑动；
- 当前场景窗口约 310 × 390pt；
- 使用 3:4 或 4:5 的沉浸式画面比例；
- 背景画面占据整个场景窗口；
- 标题、关系与一句描述叠加在画面底部；
- 使用从透明到暖灰色的渐变保证文字可读；
- 窗口边缘逐渐融入奶油晨雾背景；
- 不要放在明显的白色 App Card 里；
- 圆角约 28–32；
- 阴影保持柔和；
- 滑动时中心场景轻微放大到 1，旁边场景缩小到 0.94；
- 切换使用 260–320ms、接近临界阻尼的弹簧；
- 不使用强烈 3D 旋转。

场景窗口底部包含：

- 场景名称；
- 一句场景描述；
- 可覆盖的关系类型；
- 小型按钮“进入场景”。

场景窗口上可以使用很轻的文字：

“内置场景”

不要使用“候选”“草稿”“已完成”等状态标签。

## 二、三个内置场景

### 1. 深夜通话

关系：

- 恋人；
- 朋友；
- 异地家人。

核心情绪：

- 等待；
- 误解；
- 未回复。

典型动作：

- 发送；
- 接听；
- 挂断；
- 沉默；
- 重新开口。

场景画面：

- 暖色深夜窗边；
- 手机屏幕的微弱光；
- 窗外远处灯光缓慢变化；
- 窗帘或光影非常轻地移动；
- 不使用大面积纯黑和高饱和深蓝；
- 保持温暖、不刺眼的夜间氛围。

标题文案：

“深夜通话”

描述：

“有些话，隔着一通电话才说得出口。”

### 2. 家中餐桌

关系：

- 父母；
- 家庭；
- 伴侣。

核心情绪：

- 冲突；
- 压抑；
- 未被理解。

典型动作：

- 反驳；
- 坦白；
- 解释；
- 保护自己；
- 暂时离开。

场景画面：

- 奶油暖黄色餐桌灯；
- 碗中蒸汽缓慢上升；
- 窗外光线有极轻变化；
- 桌面物体保持克制；
- 熟悉、略有压力但依然安全；
- 不设计成阴森或戏剧化家庭冲突。

标题文案：

“家中餐桌”

描述：

“最难说出口的话，常常发生在最熟悉的地方。”

### 3. 离开的路上

关系：

- 恋人；
- 朋友；
- 同学；
- 同事。

核心情绪：

- 遗憾；
- 告别；
- 错过。

典型动作：

- 叫住；
- 追上；
- 说出遗憾；
- 正式告别；
- 选择放手。

场景画面：

- 黄昏或清晨的道路；
- 路灯和树影缓慢向后移动；
- 风轻轻吹动树叶或衣角；
- 不出现明确城市地标；
- 保留用户投射空间；
- 整体使用暖杏、奶油黄和低饱和雾蓝。

标题文案：

“离开的路上”

描述：

“有些告别，也许还来得及换一种说法。”

## 三、自由创建入口

三个内置场景下方放置一个与场景窗口明显不同的自由创建入口。

标题：

“描述一个你想进入的场景”

辅助文字：

“你来说发生了什么，我们替你搭好片场。”

入口视觉：

- 使用一个柔和发光的语音按钮；
- 按钮周围有缓慢扩散的奶油黄色与淡杏色光晕；
- 不使用大面积白色功能卡；
- 可以显示轻微声波；
- 声波只在用户说话时出现；
- 提供弱化文字输入入口。

用户点击后进入全屏口述模式。

提示：

“说说你在哪里、谁在你面前，以及发生了什么。”

用户可以一次性说完，Agent 不在口述过程中连续打断。

示例：

“我想回到上周和朋友吵架之后。地点在学校门口，她准备打车离开。她平时比较敏感，生气后会假装不在意，但其实很希望我先道歉。我想试着把她叫住。”

Agent 自动整理为：

- 地点：学校门口；
- 人物：朋友；
- 对方当前行动：准备离开；
- 对方性格：敏感、表面冷淡、希望对方先行动；
- 用户想尝试：叫住她并道歉。

只在缺少关键内容时追问一个问题，不要让用户填写复杂长表单。

## 四、进入场景前的人物设定

用户选择内置场景或完成自由口述后，不要立即进入场景。

场景背景先以模糊状态铺满屏幕，再从底部升起人物设定面板。

流程：

1. 对面是谁；
2. 用户描述对方性格；
3. Agent 整理成人物卡；
4. 用户确认；
5. 进入场景。

### 步骤一：对面是谁

标题：

“这个场景里，谁在你面前？”

字段：

- 名字或称呼；
- 与用户的关系；
- Agent 在当前场景中扮演谁。

内置场景可以根据关系提供建议，但不能替用户决定。

家中餐桌的黑客松版本一次只让 Agent 扮演一个主要人物，其他家庭成员只作为环境存在，不同时生成多个复杂角色。

### 步骤二：描述性格

标题：

“像向一个没见过 TA 的朋友那样，介绍一下 TA。”

提示：

“TA 平时怎么说话？遇到冲突时会怎样？有什么话总是不愿意直接说？”

支持语音与文字。

不要使用人格参数、滑杆、性格测试、MBTI 或情绪数值。

### 步骤三：Agent 人物卡

Agent 将用户描述整理为 3–5 条可理解的人物特征。

示例：

“妈妈，在这场对话中：”

- 说话直接，语气偏强势；
- 关心你，但不擅长直接表达；
- 遇到冲突时容易先防御和指责；
- 很少主动承认自己说重了；
- 担心常常表现为批评。

按钮：

- “有一点不像”
- “就是这样的，进入场景”

点击“有一点不像”后，用户可以用一句话补充，Agent 更新人物卡。

面板底部清楚但克制地提示：

“人物设定仅用于本次场景，离开后会清除。”

不要提供“保存人物”“添加到联系人”或跨场景复用入口。

## 五、人物形象

场景中的对方需要有一个明确形象，但不追求真实。

使用可替换的半抽象人物立绘占位：

- 半身或胸像构图；
- 轮廓清晰；
- 面部细节简化；
- 柔和插画、纸片感或轻度 3D 渲染；
- 不使用照片级人脸；
- 不尝试复刻真实人物；
- 不要求复杂口型同步；
- 不使用恐怖的写实数字人；
- 人物形象组件支持后续替换为团队提供的资源。

人物通过克制动作表达状态：

- 呼吸；
- 眨眼；
- 轻微重心变化；
- 转开视线；
- 低头或抬头；
- 抱臂或松开；
- 想开口时轻微吸气；
- 听到重要内容时身体略微靠近。

不要使用夸张表情和大幅肢体动画。

## 六、场景体验页面

进入场景后使用全屏、第一视角构图。

背景占据整个屏幕，人物位于中景，语音和字幕位于下方。

画面层级：

1. 微动效环境背景；
2. 半抽象人物立绘；
3. 对方最近一句字幕；
4. 用户语音控制；
5. 暂停和安全退出。

### 背景微动效

只允许：

- 灯光缓慢变化；
- 蒸汽上升；
- 雨滴；
- 风和树影；
- 远处车辆或窗外光点；
- 极轻的环境粒子。

禁止：

- 整个背景持续大幅缩放；
- 快速镜头移动；
- 强烈视差；
- 闪烁；
- 高速粒子；
- 频繁切换背景。

Reduce Motion 下使用静态背景和短透明度变化。

### 对话方式

不要把体验做成普通聊天页面。

- 对方说话时，Agent 使用语音；
- 同步字幕出现在人物下方；
- 默认只显示最近一句；
- 完整对话记录收在可展开面板中；
- 用户通过底部中央的语音按钮说话；
- 支持点击说话或按住说话；
- 提供弱化文字输入；
- 用户说话时人物进入倾听姿态；
- Agent 回应时人物有轻微姿态变化；
- 用户可以自由表达，不强制选择固定答案。

底部操作：

- “换一种说法”
- “暂停”
- “离开场景”

顶部只保留：

- 场景名称；
- 当前对方称呼；
- 安全退出入口。

不要使用关卡进度、好感度、情绪分数或成功率。

### 场景中纠正人物

暂停面板增加：

“TA 不太像”

用户可以补充一句，例如：

“她不会这么快原谅我。”

Agent 从下一轮开始调整当前人物表现，不重置场景。

该修正只在本场景有效。

## 七、离开与结束

片场首页不展示已完成场景。

用户主动结束时，只显示一次轻量收束页面：

“这一次，你说出了：”

突出一句用户刚刚表达的重要话，例如：

“我其实一直很在意。”

操作：

- “把这句话留下”
- “再试一次”
- “直接离开”

“把这句话留下”只保存这句话或用户确认的简短感受到“长久珍藏”，不保存完整场景、不保存人物性格和敏感对话。

“直接离开”后清除：

- 当前人物性格；
- 人物修正；
- 完整场景对话；
- 临时生成的人物信息。

不创建“已完成场景”列表。

## 八、视觉风格

延续 Morning 的奶油晨雾：

- 页面底色 `#FFFBF3`；
- 奶油主色 `#F6E7A8`；
- 淡杏 `#F3D8C7`；
- 雾蓝 `#DFE7F5`；
- 淡薰衣草 `#E9E4F3`；
- 主文字 `#4B463F`；
- 低饱和、高明度、柔和暖色；
- 页面背景使用 3–5 个 Layer Blur 100–150 的大色团；
- 场景画面可以比普通页面更有纵深，但不要突然变成深色游戏界面；
- 夜间场景使用暖色低亮度，而不是纯黑；
- 不使用高饱和绿、霓虹紫和蓝绿医疗色；
- 不使用相同白色大卡片堆叠；
- 场景选择页有电影感，但不要加入胶片孔、场记板等过度直白的影视符号。

## 十、必须实现的原型路径

路径一：

片场首页 → 滑动三个内置场景 → 选择“深夜通话” → 填写对面是谁 → 语音描述性格 → 查看人物卡 → 确认 → 进入场景 → 用户说话 → Agent 扮演对方回应 → 暂停 → “TA 不太像” → 调整 → 继续 → 结束 → 保存一句话或直接离开。

路径二：

片场首页 → “描述一个你想进入的场景” → 用户口述 → Agent 整理场景 → 用户确认 → 描述人物性格 → 进入场景。

确保：

- iPhone 393 × 852 pt 下无横向裁切；
- 场景首页可以横向滑动；
- 底部 App Tab Bar 在片场首页固定；
- 进入沉浸场景后隐藏 App Tab Bar；
- 用户可以随时暂停和退出；
- 退出后人物性格与敏感场景数据被清除；
- 不展示已完成场景；
- 不改变陪伴、信箱和我的页面。

最终效果应更接近一个克制、温柔的 AI 模拟人生片段：用户进入关系情境，自由开口，Agent 成为对面的人并实时回应；但产品始终提醒用户这是一次模拟表达，而不是真实人物、真实记忆或心理治疗。
